# PseudoLang — Minimal Programming DSL

A simple pseudo programming language designed to describe software logic without depending on any specific programming language.
PseudoLang is intended to be translated by an LLM into real programming languages such as Python, JavaScript, Java, or Kotlin.

The goal is to allow people with **logical thinking** to describe complete software systems without worrying about syntax, frameworks, or platform details.

---

# Design Goals

* Extremely **small syntax**
* **Human-readable**
* **LLM-friendly**
* Abstract away language-specific details
* Capable of representing **any application logic**
* Suitable for **backend services, web apps, mobile apps, and APIs**

PseudoLang describes **logic and structure only**.
Frameworks, libraries, and infrastructure are generated by the LLM.

---

# Language Rules

1. All **keywords are lowercase**
2. Identifiers use **snake_case**
3. Types are **optional**
4. Database, HTTP, and framework details are **not written in PseudoLang**
5. Control flow uses **only minimal constructs**

---

# Keywords

PseudoLang intentionally uses a very small set of keywords.

```
module
model
type
error
field
function
stream
let
set
add
if
else
for
return
call
end
```

Total keywords: **16**

---

# Core Concepts

## Modules

Modules group related code.

```
module messaging

function send_message(user, text)
    call deliver(user, text)
end

end
```

---

## Models (Data Structures)

Models represent structured data.

```
model message

field id
field user_id
field text
field created_at

end
```

Equivalent to a class/struct in most languages.

---

## Union Types

Union types represent one of several variants.

```
type part

text_part
file_part
tool_part
reasoning_part

end
```

Equivalent to unions/enums in modern languages.

---

## Errors

Errors describe structured failure types.

```
error validation_error

field code
field message

end
```

---

## Functions

Functions contain program logic.

```
function is_media(mime)

if mime starts_with "image/"
    return true
end

if mime == "application/pdf"
    return true
end

return false

end
```

---

## Streams (Async Generators)

Streams represent asynchronous data flows.

```
stream message_stream(session_id)

call subscribe(session_id)

end
```

---

## Variables

Variables are declared with `let`.

```
let total = 0
```

---

## Mutation

Fields can be updated using `set`.

```
set user.name = "Alice"
```

---

## Collections

Items can be added to collections.

```
add item to items
```

---

## Conditionals

PseudoLang uses a minimal conditional structure.

```
if score > 90
    return "A"
else
    return "B"
end
```

---

## Loops

Only one loop type exists.

```
for item in items

call process(item)

end
```

This is enough to represent iteration in any programming language.

---

## Function Calls

Function calls are explicit.

```
call send_email(user)
```

# Complete Example

```
module media

model file

field id
field mime
field url

end


function is_media(mime)

if mime starts_with "image/"
    return true
end

if mime == "application/pdf"
    return true
end

return false

end


function collect_media(files)

let result = []

for f in files

if call is_media(f.mime)
    add f to result
end

end

return result

end

end
```

# Translation Model

PseudoLang is designed to be translated by an LLM into real code.

Example pipeline:

```
PseudoLang
   ↓
Intermediate Representation (optional)
   ↓
Target Language Code
```

Target languages may include:

* Python
* JavaScript
* Java
* Kotlin
* Go
* Swift

---

# What PseudoLang Is Good For

PseudoLang works very well for:

* backend services
* APIs
* SaaS platforms
* automation systems
* business logic
* mobile applications
* web applications

---

# What PseudoLang Is NOT Designed For

PseudoLang is not intended for:

* operating systems
* compilers
* game engines
* GPU programming
* low-level embedded systems

---

# Summary

PseudoLang provides a **minimal universal programming description language** with:

* **16 keywords**
* simple control flow
* clear data modeling
* framework-independent logic

It allows software to be described in a **language-neutral format** that can be translated by LLMs into real programming languages.
